# ResumeGo 当前基线

更新日期：2026-08-19

本文档记录产品重置开始时的真实状态。它不是目标设计，也不用于美化现有完成度；后续整改以此判断产品是否真正变得更简单、可信和可交付。

## 当前形态

ResumeGo 当前是一套前后端分离的 Web 应用：

- Vue 3 + TypeScript + Vite 前端；
- Java 21 + Spring Boot 后端；
- MyBatis-Plus + Flyway + MySQL 数据层；
- 外部大模型提供解析、建议和面试内容；
- Docker Compose 辅助本地运行。

当前运行仍依赖 Node.js、Java 和 MySQL 环境，不具备普通用户下载安装后直接使用的条件。

## 已有能力

- 结构化简历和经历编辑；
- 简历版本及部分差异展示；
- 简历诊断和岗位差距分析；
- 基于岗位上下文的 AI 修改建议；
- 模拟面试、多轮记录和复盘；
- 岗位展示与管理；
- PDF 相关导出能力；
- 后端单元与集成测试基础。

这些能力说明核心业务已经存在，但页面入口、数据关系和用户任务仍没有被收束为一个清晰产品。

## 主要产品问题

1. 首次打开时存在演示数据和个人内容，用户难以判断哪些数据属于自己。
2. 页面按照功能模块组织，缺少“为某个岗位完成一次准备”的任务主线。
3. 简历编辑器信息密度过高，编辑、诊断、版本和 AI 操作同时争夺注意力。
4. 部分操作缺少明确的加载、成功、失败或空状态反馈。
5. AI 建议尚未完整形成“问题—证据—建议—差异—新版本”的可追溯链路。
6. 模拟面试入口和历史记录混在同一工作区，异常或中断记录影响信任。
7. 岗位库包含大量无法稳定证明来源与时效的数据，不适合作为核心价值。
8. 产品仍保留明显的演示项目和功能堆叠感。

## 主要工程问题

- 前端缺少自动化测试和稳定的状态管理落点。
- `HomeView.vue` 与 `InterviewView.vue` 均已超过四千行，职责过多。
- 前端生产构建主 JavaScript 包约 1 MB，首屏与维护成本偏高。
- 后端部分服务类体积过大，应用编排、规则和外部模型调用边界需要继续拆分。
- 当前 MySQL 和环境配置不适合直接随桌面应用分发。
- 尚无 Electron 主进程、桌面 IPC、安全存储、安装包、代码签名或更新链路。

## 验证基准

产品重置开始时：

- 前端 `npm run build` 可以通过；
- 后端 `mvn test` 可以通过，共 410 项测试，0 项失败、1 项跳过；
- 前端没有独立自动化测试命令；
- 仓库尚未产生可供普通用户安装的桌面发行包。

测试数量只作为迁移参考，后续更看重核心用户流程是否有稳定、可重复的验收。

## 保留、重做与移除

### 保留

- 能力证据、简历版本、目标岗位和面试反馈之间的数据思想；
- Vue 与 Spring Boot 中可复用的业务能力；
- 结构化模型输出、错误降级和自动化测试基础；
- 用户最终决定、AI 不编造事实等可信原则。

### 重做

- 以“求职项目”为中心的信息架构；
- 首次启动、空状态和示例数据机制；
- 简历修改建议及版本生成流程；
- 模拟面试创建、进行、复盘和历史体验；
- 本地数据库、桌面进程和发布方式；
- 前端组件边界、状态管理和测试。

### 移除或降级

- 默认个人数据和未经说明的演示记录；
- 无法保证来源、真实性和时效的公共岗位库；
- 只为展示功能数量而存在的入口；
- 与个人产品无关的团队、课程和验收流程。

## 重置完成的判断

第一阶段不是以页面数量判断成功，而是以一个新用户能否独立完成以下任务判断：

> 安装并打开 ResumeGo，创建一个求职项目，录入真实经历和目标岗位，完成一次有证据依据的简历修改，并随时导出或删除自己的数据。
