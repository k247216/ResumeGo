# ResumeGo 桌面工作台基础设计

## 目标

将 ResumeGo 从以简历编辑器为中心的 Web 原型，逐步改造成以真实求职目标为中心、同时允许用户先整理本地资料的桌面工作台。

本设计固定产品对象、信息架构、进程职责和安全边界，不固定最终视觉风格。颜色、动效、图标和精细布局在核心流程稳定后继续优化。

## 产品对象

### 本地资料

本地资料不依赖任何求职目标，可以单独创建、导入和维护：

- 简历及不可变版本；
- 能力证据；
- 用户保存的岗位描述；
- 后续支持的本地附件。

### 求职目标

产品界面统一使用“求职目标”，不向用户展示“求职项目”这一名称。后端现有 `JobProject` 可以暂时保持内部命名，前端文案与类型逐步使用 `Target` 或 `ApplicationTarget`。

一个求职目标关联：

- 公司和目标岗位；
- 当前采用的简历版本；
- 相关能力证据；
- 定向诊断与修改记录；
- 面试准备、记录和后续行动。

求职目标是本地资料的上下文容器，不复制简历正文，也不要求用户重新录入项目经历。

### 项目经历与能力证据

“项目经历”只表示用户简历中的真实经历。导入或填写的经历在用户确认后成为能力证据，供定向优化引用。

ResumeGo 所说的可信是“来源可追溯且经过用户确认”，不是对经历真实性进行外部背书。

## 启动状态

同一个工作台根据本地数据自动进入不同状态。

### 没有本地资料

首屏提供：

1. 导入 Markdown 简历；
2. 创建空白简历；
3. 粘贴目标岗位并开始准备。

不强迫用户先创建求职目标。

### 有简历但没有求职目标

进入本地资料工作台，展示已有简历、待确认的经历证据和继续编辑入口。用户可以随时通过“针对岗位开始优化”创建求职目标。

### 存在求职目标

默认恢复最近使用的进行中目标，显示：

- 当前岗位和使用的简历版本；
- 材料完整情况；
- 明确的下一步行动；
- 定向优化和面试准备入口。

如果存在多个目标，“全部求职目标”提供类似管线或列表的管理视图，但不把复杂看板作为默认首页。

## 前端信息架构

### 稳定应用外壳

桌面端采用固定左侧导航：

- 工作台；
- 求职目标；
- 简历；
- 能力证据；
- 设置。

第二级上下文栏根据当前区域展示进行中的求职目标或本地资料。主内容区域承担当前任务。

公共岗位市场、岗位探索、岗位推荐、简历总分、通知中心、资源商城和社交入口不进入产品界面。评分与岗位匹配的现有实现保留在代码中，但隐藏入口并停止继续开发，后续只有在产品重新立项后才恢复。

### 目标驾驶舱

目标驾驶舱采用已确认的 A 型结构：下一步行动优先，其次是岗位、当前简历、证据和面试准备状态。

吸收 B 型编辑效率：点击当前简历后进入沉浸式编辑模式，保留目标面包屑、保存状态和返回驾驶舱入口，不再把编辑器作为应用首页。编辑器只承载正文编辑、版本、撤销重做、模板与排版、实时预览和 PDF 导出。

目标岗位录入、能力证据、定向优化和面试准备归入目标驾驶舱。阶段 A 不接入 AI 建议，避免把旧编辑器中混杂的功能入口原样搬入新界面。

吸收 C 型管理能力：多个求职目标可以按状态筛选或分组，但状态改变必须来自用户操作或确定性规则，AI 不得决定目标阶段。

## Markdown 导入

首期导入格式为 UTF-8 Markdown 文件。

```text
Electron 文件选择
→ Vue 显示文件名、大小和导入说明
→ Spring Boot 读取受控临时内容并进行确定性结构解析
→ 创建导入来源与简历初始版本
→ 可选 AI 抽取候选经历证据
→ 用户查看原始引用、修改并逐条确认
→ 已确认内容进入能力证据库
```

约束：

- 确定性解析不调用外部模型；
- AI 抽取必须由用户主动触发，并说明将发送的内容；
- 候选证据在用户确认前不能作为简历修改事实；
- 每条候选证据保留来源版本、段落引用和抽取状态；
- 文件过大、编码错误、结构无法识别时不创建半成品版本；
- 首期不承诺 PDF 和 DOCX 的高质量结构解析。

## 进程与打包职责

### Electron 主进程

- 管理窗口、系统菜单和应用生命周期；
- 选择导入文件、导出位置、数据目录和备份目录；
- 启动、健康检查和停止 Spring Boot 子进程；
- 生成随机本地端口和单次会话凭证；
- 使用系统安全存储保存模型密钥；
- 提供更新和安装包信息。

Electron 主进程不实现求职业务规则，也不直接修改数据库。

### Vue 渲染进程

- 实现所有用户可见界面和交互状态；
- 组合工作台、目标、简历、证据和面试流程；
- 通过本地 HTTP 调用 Spring Boot；
- 通过白名单 preload API 请求文件选择等系统能力；
- 不直接访问 Node.js、任意文件路径或子进程。

### Spring Boot 本地进程

- 实现业务校验、所有权、事务、版本和持久化；
- 解析 Markdown 内容并管理导入记录；
- 校验模型输出并维护证据引用；
- 只监听 `127.0.0.1` 的随机端口；
- 校验 Electron 启动时生成的会话凭证；
- 收到退出信号后完成落盘并安全结束。

### H2 文件数据库

- 数据文件放在操作系统用户数据目录；
- 路径由 Electron 明确传入；
- Flyway 管理结构升级；
- 数据库和附件目录共同组成备份范围；
- 安装包升级失败不能覆盖原始数据。

## 前端代码边界

现有 `HomeView.vue` 和 `InterviewView.vue` 体积过大，不能继续承载新工作台逻辑。

目标结构：

```text
layouts/
  DesktopShell.vue
views/workbench/
  WorkbenchView.vue
  FirstRunView.vue
views/targets/
  TargetListView.vue
  TargetDashboardView.vue
views/resumes/
  ResumeLibraryView.vue
  ResumeEditorView.vue
views/evidence/
  EvidenceLibraryView.vue
stores/
  workspace.ts
  targets.ts
  resumes.ts
composables/
  useWorkspaceLaunch.ts
  useAsyncState.ts
```

页面负责组合，API 数据和跨页面状态进入 store/composable。新编辑器不得整体复用 `HomeView.vue`；只迁移仍在产品范围内的编辑能力，完成替代后再移除旧路由。评分和岗位匹配的前后端源码暂时保留，但不被新界面调用。

## 错误与恢复

- 后端未启动：显示本地服务启动失败及重试，不展示空数据假象；
- 数据迁移失败：停止打开工作台，保留原数据并提供日志导出入口；
- Markdown 导入失败：不创建不完整简历，允许重新选择文件；
- 模型不可用：仍可导入、编辑、保存版本和手工确认证据；
- 编辑未保存：切换目标或关闭窗口前明确提示；
- 最近目标不存在或已归档：回到目标列表，不自动创建替代目标；
- 桌面进程异常退出：下次启动进行数据库完整性和未完成导入检查。

错误提示不得包含简历正文、模型密钥、会话凭证或本地绝对路径。

## 测试与验收

### 前端

- 三种启动状态；
- 创建和切换求职目标；
- 无目标资料模式；
- Markdown 导入成功、失败和取消；
- 异步加载失败与重试；
- 编辑器返回目标驾驶舱时保留上下文。

### 后端

- Markdown 结构解析和原子导入；
- 候选证据在确认前不可用于建议；
- 求职目标、简历版本和岗位的用户隔离；
- H2 文件重启持久化和 Flyway 升级；
- 退出时事务完成且数据库可再次打开。

### 桌面端

- 全新安装首次启动；
- 本地后端启动、健康检查和退出；
- 渲染进程无任意 Node.js 权限；
- 数据目录、文件选择、备份恢复；
- 无 Java、Node.js 和 MySQL 的全新设备可以运行安装包。

## 分阶段实施

### 阶段 A：工作台骨架

完成前端测试基础、稳定桌面式应用外壳、三种启动状态、求职目标创建与切换，并建立不含评分、岗位推荐和岗位库入口的专注编辑器。继续使用当前 Web 开发环境和 MySQL。

### 阶段 B：Markdown 导入与证据确认

实现原子导入、来源记录、候选证据确认和无目标资料模式。AI 抽取作为可选能力，晚于确定性导入。

### 阶段 C：H2 文件模式

处理 MySQL 专用迁移，验证文件持久化、升级失败保护和备份恢复。

### 阶段 D：Electron 最小链路

实现主进程、受控 preload、本地后端生命周期和开发启动命令。

### 阶段 E：安装包与发布

携带 Java 运行时，构建首个 Windows 安装包，再验证 macOS；补充签名、版本、更新和 GitHub Releases 流程。

每个阶段独立提交、验证和复核。阶段 A 完成前不并行重做完整视觉系统，阶段 C 通过前不承诺正式安装包。

## 非目标

- 不在本轮实现云同步、登录、团队协作和遥测；
- 不引入公共岗位市场和自动投递；
- 不在产品界面暴露岗位探索、岗位推荐、简历总分、评分或岗位匹配；
- 不删除评分和岗位匹配的既有后端与算法源码，只冻结其产品开发；
- 不让 AI 自动接受建议或改变求职目标状态；
- 不同时重写 Vue、Spring Boot 或现有简历编辑器；
- 不在第一版追求多平台完全一致的安装体验。
