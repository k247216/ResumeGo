# ResumeGo 本地 AI Provider 配置设计

## 目标

为 ResumeGo 建立适合本地桌面产品的模型配置能力，让用户可以使用自己的模型账号完成简历诊断、定向优化和模拟面试，同时不影响不使用 AI 的本地编辑流程。

本设计覆盖 Provider 协议、配置资料、密钥边界、运行期装载、连接测试和首次使用体验。它不恢复评分、岗位匹配或岗位推荐，也不允许模型输出直接改变业务状态。

## 产品原则

- AI 是可选能力。未配置模型时，简历创建、导入、编辑、版本管理和导出仍然可用。
- 首次启动不强迫用户填写 API Key；首次主动使用 AI 时再给出配置引导。
- 用户看到的是“模型服务”，不是底层 SDK、网关或环境变量。
- 配置错误必须能在设置页被发现，不能等到生成简历时才暴露。
- ResumeGo 不提供公共中转密钥，也不把用户密钥上传到 ResumeGo 自有服务。

## Provider 模型

### 协议类型

第一版只实现三种稳定协议：

1. `openai-compatible`：OpenAI 以及兼容其 Chat Completions 和 Models API 的服务；
2. `anthropic`：Anthropic Messages API；
3. `gemini`：Google Gemini GenerateContent API。

DeepSeek、智谱 GLM、通义千问和 Moonshot 作为 `openai-compatible` 的预设出现。预设只填写建议的名称和 Base URL，用户仍可修改模型名称和地址。New API 等用户自建中转站使用“自定义 OpenAI 兼容”预设，不作为 ResumeGo 的依赖。

### 配置资料

每份配置资料包含：

- 本地唯一 ID；
- 用户可修改的显示名称；
- 协议类型；
- Base URL；
- 默认模型；
- 是否为当前默认配置；
- API Key 是否已配置；
- 最近一次连接测试的时间与结果摘要。

非敏感字段由本地后端持久化。接口只能返回 `apiKeyConfigured`，不得返回 API Key 或可逆密文。

第一版允许保存多份配置，但同一时间只选择一份默认配置。功能级模型分配、自动路由、故障切换、费用统计和负载均衡不进入当前范围。

## 密钥与进程边界

### 桌面正式模式

Electron 主进程负责密钥持久化：

- 使用 Electron `safeStorage` 加密 API Key；
- 加密结果写入应用 `userData` 目录中的独立密钥文件；
- Vue 渲染进程只在用户本次输入时短暂持有明文，不能读取已经保存的密钥；
- preload 只暴露 `saveApiKey(profileId, value)`、`deleteApiKey(profileId)`、`hasApiKey(profileId)` 等白名单能力；
- 密钥文件不进入普通数据导出或备份；
- 日志、异常消息、数据库和 Git 仓库中不得出现密钥、Authorization Header 或密钥文件内容。

Electron 启动 Spring Boot 后，通过仅绑定 `127.0.0.1`、携带单次会话凭证的内部接口，把当前默认配置与解密后的密钥装载到后端内存。后端不持久化明文密钥。切换默认配置或更新密钥时重新装载，不要求重启应用。

### Web 开发模式

Web 开发模式允许使用当前本地服务会话的临时 API Key：

- 非敏感配置仍保存在本地后端；
- API Key 通过本地会话接口装载到 Spring Boot 内存，不写入 `localStorage`、`sessionStorage`、Cookie、日志或数据库；
- 本地服务重启后需要重新输入；
- 界面明确标注“开发模式：密钥不会保存”。

不以明文文件作为系统安全存储失败时的自动降级方案。安全存储不可用时，应用应说明原因并允许仅本次会话使用。

## 后端架构

### 配置存储

新增独立的 `ai_provider_profiles` 表保存非敏感配置。Provider 配置不继续复用启动环境变量作为产品设置；环境变量仅保留为开发和迁移兼容入口。

### 运行期注册表

新增内存态 `AiRuntimeRegistry`：

- 保存当前默认 Profile 的协议、地址、模型和密钥；
- 原子替换完整配置，避免请求读到半更新状态；
- 未装载或密钥缺失时返回 `not_configured`，不偷偷切换到 Mock；
- 测试环境可以显式注入 Mock，生产请求不把 Mock 内容伪装成真实模型结果。

现有 `AiClientSelector` 的启动期二选一逻辑由运行期注册表取代。现有 `QwenMaxProvider` 重命名并收敛为通用 `OpenAiCompatibleClient`；Anthropic 和 Gemini 分别使用独立客户端，三者实现相同的 `AiClient` 接口。

所有 Provider 输出继续经过现有结构化校验与业务验证。模型不得设置求职目标状态、评分权重、岗位排序或面试状态机。

### 本地接口

提供以下受本地会话凭证保护的接口：

- `GET /api/ai/providers`：读取非敏感配置与密钥存在状态；
- `POST /api/ai/providers`：创建配置资料；
- `PUT /api/ai/providers/{id}`：修改非敏感配置；
- `DELETE /api/ai/providers/{id}`：删除非敏感配置；Vue 通过 preload 协调删除对应的桌面密钥，任一步失败都提示用户重试；
- `PUT /api/ai/providers/{id}/default`：设为默认配置；
- `POST /api/ai/runtime/apply`：桌面主进程装载当前配置与密钥，仅接受本地会话；
- `POST /api/ai/providers/test`：使用尚未保存或已经保存的配置进行连接测试；
- `POST /api/ai/providers/models`：按协议获取可用模型列表，失败时仍允许手工填写模型名。

面向 Vue 的普通读取接口永远不返回密钥。`runtime/apply` 在 Electron 阶段进一步限制为主进程生成的内部凭证，不能复用普通页面请求身份。

## 设置界面

设置页增加“AI 模型”区域：

- 顶部显示“未配置 / 可用 / 连接异常”状态；
- 左侧或上方列出已保存配置；
- 编辑区包含服务预设、协议、Base URL、API Key 和模型；
- API Key 输入框默认隐藏，只表达“已保存”状态，不回填旧值；
- 修改其他字段时不要求重新输入已有 Key；
- 提供“获取模型”“测试连接”“保存并设为默认”三个明确动作；
- 删除配置前说明不会删除任何简历或求职目标数据。

首次调用 AI 且未配置时，展示轻量引导：说明需要用户自己的 API Key，并提供“去配置”和“暂不使用”两个动作。首屏工作台不增加永久悬浮聊天按钮。

## 数据流

```text
用户在设置页填写配置
→ Vue 校验必要字段
→ Spring Boot 保存非敏感 Profile
→ preload 请求 Electron safeStorage 保存 API Key
→ Electron 使用内部会话把默认 Profile + Key 装载进后端内存
→ 后端执行连接测试
→ Vue 只接收脱敏状态与错误分类
```

AI 功能调用时：

```text
业务服务构造受约束请求
→ AiRuntimeRegistry 取得当前客户端
→ Provider 请求
→ 响应结构化校验
→ 证据与禁飞区校验
→ 用户审查后才能写入新简历版本
```

## 校验与错误

- Base URL 只允许 `https`；开发模式可允许明确的 `http://127.0.0.1` 与 `http://localhost`。
- 模型名、显示名称和地址去除首尾空白并限制长度。
- 连接测试设置连接与响应超时，且错误信息不得包含响应请求头或完整上游响应体。
- 统一错误分类：`not_configured`、`authentication`、`permission`、`rate_limit`、`timeout`、`invalid_response`、`network`、`provider_error`。
- 获取模型列表失败不阻止保存手工模型名。
- 更新配置失败时保留表单内容；更新密钥失败时不能把 Profile 标为可用。
- 删除默认配置后不自动选择并调用另一份配置，用户必须明确设定新的默认项。

## 测试与验收

### 后端

- Profile 创建、更新、删除、默认项唯一性和跨用户隔离；
- 响应不包含密钥字段；
- 运行期配置原子替换与未配置错误；
- 三种协议的请求格式和响应解析；
- 连接错误分类与日志脱敏；
- 非法 URL、空模型和超长字段校验；
- 模型输出仍经过结构化校验。

### 前端

- 空配置、已配置和连接失败状态；
- 预设切换只更新建议字段，不覆盖用户主动编辑的值；
- 已保存 Key 不回填；
- 测试连接、获取模型、保存失败和重试；
- 未配置时的 AI 使用引导；
- Web 开发模式刷新后密钥消失且无浏览器持久化。

### Electron

- 渲染进程无法读取明文 Key；
- `safeStorage` 加密、更新和删除；
- 正常启动与切换配置后后端内存装载成功；
- 安全存储不可用时进入明确的会话模式；
- 日志、数据库、普通备份和 Git 状态中不存在密钥。

## 在既有路线图中的交付位置

以下 AI 编号只用于描述依赖关系，不形成独立产品主线，也不要求逐项提交。开发仍严格沿用 `RG-004 → RG-005 → RG-006` 的顺序：先完成工作台与面试界面收束，再验证 H2 文件数据库和 Electron 桌面链路。API 配置在进入相关主线阶段时一并落地。

### AI-001：配置领域与 Web 开发闭环

在 RG-004 完成、RG-005 验证本地文件数据库时，实现 Profile 数据模型、运行期注册表、OpenAI-compatible 客户端、脱敏接口、设置界面、临时会话 Key 和连接测试。保留现有环境变量兼容，但界面调用不得伪装 Mock 为真实结果。

### AI-002：Anthropic 与 Gemini 原生协议

在 AI-001 的同一配置模块中加入两种原生客户端、模型列表和协议测试，不增加功能级模型路由。

### AI-003：Electron 安全存储接入

随 RG-006 桌面链路实现 preload 白名单、`safeStorage`、内部运行期装载和会话模式降级，不提前建立临时桌面壳。

### AI-004：首次使用与打包验收

随桌面打包验收接入 AI 功能前置检查，在 Windows 与 macOS 开发包中验证保存、重启、切换、删除和日志脱敏。

各阶段与工作台、H2 和 Electron 主线一起计划性提交，不为每个输入框单独提交。

## 非目标

- 不提供 ResumeGo 托管的公共模型 Key 或代理服务；
- 不实现自动选择最便宜或最快模型；
- 不实现多 Key 轮询、负载均衡和自动故障转移；
- 不同步、导出或备份 API Key；
- 不恢复岗位推荐、评分和岗位匹配；
- 不允许 AI 自动接受简历建议或改变面试状态；
- 不把通用聊天窗口作为工作台的核心入口。
