# V2 Knowledge Library Desktop Interaction Design

Status: User-approved visual direction for `V2-F2-UX-01`

Approved target: [`docs/design/v2-knowledge-library-target.png`](../../design/v2-knowledge-library-target.png)

## Product outcome

Knowledge Library 是本地职业资料工作区，不是上传中心、AI 聊天页或文件系统替代品。用户应当可以沿着同一条真实路径完成：

```text
找到资料 → 阅读或定位命中内容 → 确认来源状态 → 分类整理 → 打开受管原文 → 重试或彻底删除
```

页面可以借鉴 Obsidian 的多栏效率、层级导航和快速切换，但使用职达的职业资产语义，并维持比 Obsidian 更松弛的视觉密度。

## Page responsibility

页面负责：

- 导入当前支持的本地文件和创建本地笔记；
- 用层级资料库和标签定位资料；
- 展示真实文件类型、处理状态、更新时间和关键词命中；
- 阅读已提取正文，并从搜索命中定位到对应行；
- 在可关闭检查器中管理来源属性、分类、标签、文件动作和真实引用；
- 对可恢复失败执行重试，对删除展示影响摘要并二次确认。

页面不负责：

- RAG 对话、AI 总结、知识图谱、学习路线和完整知识训练；
- 将文档内容自动认定为用户掌握的能力；
- 展示后端尚不支持的文件格式或虚构资产关系；
- 监控用户任意目录，或把本地系统路径暴露给 renderer。

## Desktop structure

从左到右固定为五个区域：

1. 全局工具栏：复用 `DesktopShell`，Knowledge 为当前一级入口。
2. 资料库导航：层级文件夹与标签。
3. 资料列表：当前文件夹、标签或搜索结果对应的真实文档。
4. 正文阅读区：唯一视觉主体，只展示文档标题、必要状态和正文。
5. 来源检查器：可关闭的属性与关系面板。

1440×960 推荐宽度：

| 区域 | 宽度 |
| --- | --- |
| 全局工具栏 | 64–72px，沿用 Shell |
| 资料库导航 | 220px |
| 资料列表 | 330px；允许收起至 0 |
| 正文阅读区 | `minmax(460px, 1fr)` |
| 来源检查器 | 300px；允许关闭至 0 |

页面使用整个工作区画布，不再把所有内容包进一个居中大卡片。区域主要依靠间距、对齐和细分隔线区分；不使用卡片套卡片。

## Header

顶部为单行桌面命令区：

- 左：`知识库`；
- 中：全局搜索，提示“搜索资料标题、内容或标签”；
- 右：黑色主按钮 `导入资料`、次按钮 `新建笔记`；
- 不展示 AI 连接、统计指标或装饰性欢迎语。

搜索覆盖标题和已提取正文，并可叠加当前文件夹/标签筛选。搜索失败时保留旧结果必须明确标注“以下为上一次结果”。

## Library navigator

### Folder tree

`资料库` 是职业资产分类树，不是用户磁盘目录。文件夹支持：

- 展开与收起；
- 最多五级；
- 新建子文件夹、重命名和移动；
- 单个文档只属于一个文件夹；
- 选择父文件夹时默认包含其所有后代文档；
- 空文件夹仍显示；
- 含子文件夹或文档的文件夹不能静默删除。

默认视觉示例可以使用“技术知识、项目知识、面试资产、个人总结”，但空工作区不得自动写入这些示例。示例只存在于设计与虚构测试夹具中。

### Tags

标签区位于文件夹树下方并可独立收起。常用标签显示文档数量；`更多标签` 打开完整列表。标签是横向属性，不参与层级，不替代文件夹。

### Navigator collapse

导航区在窄窗口可以收起为 44px 图标轨；恢复后保持用户上次的展开节点和滚动位置。本阶段不持久化到云端。

## Document list

资料列表使用连续行和轻分隔线，不把每个文件做成卡片。

每行最多显示：

- 与真实 `sourceType/extension` 对应的图标；
- 标题；
- 所属文件夹或一个最相关标签；
- 更新时间；
- `解析中`、`可重试`、`原文件缺失` 等真实状态。

不显示当前版本不支持的 PDF、DOCX、PPTX 等图标；新增格式后由真实 extension 自动出现。

列表头包含：当前范围、排序、视图菜单和明确的收起按钮。收起资料列表后正文立即扩展；页面标题附近保留一个恢复按钮。收起状态不改变当前文档选择。

搜索结果行额外显示一个命中摘要和可选行号。点击结果时选择对应文档，并让正文滚动到真实命中位置；没有行号时只打开文档，不伪造定位。

## Reading workspace

正文是页面视觉主体：

- 标题区只展示文档标题、来源可用状态、更新时间和打开检查器按钮；
- 正文按 Markdown 阅读样式呈现，正文行宽控制在约 65–80 个中文字符；
- 搜索定位使用短暂、低饱和高亮，不改变原文；
- 正文底部不放资产关系、相关资料、文件夹位置或功能卡片；
- `NOTE` 在编辑模式下保存用户原文，AI 不参与静默改写；
- `FILE` 正文是受管副本的提取结果，只读，修改原资料需打开受管原文。

无选中文档时显示简洁空状态，引导选择资料、导入资料或新建笔记，不展示假文档。

## Closable source inspector

检查器默认在宽屏打开，在窗口变窄时默认关闭。标题为 `来源与属性`，右上角有清晰关闭按钮；正文标题附近的 inspector 图标可重新打开。

检查器按轻分隔线排列以下区块：

1. 分类：当前文件夹路径，可修改；
2. 标签：查看、添加和移除；
3. 本地来源：原始文件名、真实 availability、更新时间；不展示绝对路径、hash 或内部 token；
4. 操作：`打开原文`、`在文件夹中显示`，仅 Electron 且来源可用时启用；
5. 资产关系：仅展示真实持久化引用，如 Pipeline 或知识训练引用；关系接口可用但结果为空时显示“尚无关联”，接口尚未实现时隐藏整个区块，不得生成示例；
6. 相关资料：只使用明确、可解释的规则或后续检索结果，并标明依据；契约未实现前隐藏该区块；
7. 危险操作：删除放在底部或更多菜单，必须先展示后端 deletion-impact，再输入明确确认。

检查器关闭、切换文档和保存属性必须隔离状态；A 文档的错误不能显示到 B 文档。

## Real data and staged capability

最终视觉稿是长期开发目标，不授权前端伪造尚未存在的数据：

| 视觉能力 | 数据来源或前置任务 |
| --- | --- |
| 层级文件夹 | `V2-F2-BE-04` 分类树契约 |
| 标签和关键词搜索 | 已集成 BE-02 / FE-01 |
| 解析重试与彻底删除 | 已集成 BE-03，FE-02 接入 |
| 打开/定位受管原文 | `V2-F2-IO-02` |
| 来源安全元数据 | FE-02 只使用公开安全字段；路径由 Electron main 独占 |
| 资产关系 | 后续真实引用表；当前无数据则展示诚实空状态 |
| 相关资料 | 当前隐藏；不得用写死列表占位 |
| 更多文件格式 | 后续 IO 任务；当前只显示实际支持格式 |

## Responsive behavior

应用最小窗口仍为 1080×720。

- `≥ 1320px`：导航、列表、正文、检查器均可同时显示；
- `1160–1319px`：检查器默认关闭，可作为右侧覆盖层打开；
- `1080–1159px`：导航收起为图标轨，检查器覆盖打开，列表保持 300px；
- 用户主动收起资料列表时，正文占据释放宽度；
- 不把任一区域改成移动端纵向卡片流；
- 内容高度使用工作区内部滚动，不让整个应用产生多层横向滚动。

## Keyboard and focus

- `Cmd/Ctrl + K` 聚焦知识搜索；
- `Esc` 依次关闭对话框、检查器覆盖层和搜索建议，不清除已保存数据；
- 上下方向键移动资料选择，`Enter` 打开；
- 文件夹、标签、列表行、收起按钮和检查器按钮均可键盘聚焦；
- 收起区域后 focus 移到其恢复按钮；
- 对话框关闭后 focus 返回触发控件。

## State behavior

- 初次加载：骨架只覆盖对应区域，不让整个页面闪烁；
- 后端离线：保留已加载内容并在命令区显示非阻塞错误；
- 导入中：新增真实 PENDING 行，失败后保留可重试状态；
- 原文件缺失：保留文档和已提取正文，禁用文件操作；
- 删除成功：从树计数、列表、搜索结果和详情中同时移除；
- 删除文件失败：文档仍按后端契约删除，向用户说明清理任务可重试；
- 浏览器开发模式：`打开原文` 返回 `DESKTOP_REQUIRED`，不得伪装成功。

## Component boundary

FE-02 推荐拆分：

- `KnowledgeLibraryView.vue`：页面编排和 responsive 状态；
- `KnowledgeCommandBar.vue`：标题、搜索、导入、新建；
- `KnowledgeNavigator.vue`：文件夹树、标签与导航收起；
- `KnowledgeFolderTree.vue`：递归节点；
- `KnowledgeDocumentList.vue`：列表、搜索结果和列表收起；
- `KnowledgeReadingPane.vue`：只读正文、NOTE 编辑和命中定位；
- `KnowledgeSourceInspector.vue`：属性、来源、关系与危险操作；
- `KnowledgeDeleteDialog.vue`：影响摘要和确认；
- 已有小组件可复用，但不得保留与新结构冲突的卡片式容器。

## Acceptance scenarios

1. 在宽屏导入两份真实支持格式的虚构资料，列表图标、状态和正文来自后端。
2. 创建三级文件夹，把两份资料放到不同节点，展开/收起与父级汇总结果一致。
3. 按标签和关键词搜索，选择命中后正文定位到返回行号。
4. 收起资料列表，正文扩展；重新打开后选择与滚动状态保持。
5. 关闭右侧检查器，正文扩展；重新打开只显示当前文档属性。
6. 在 Electron 打开原文或定位文件；浏览器模式诚实提示桌面端要求。
7. A 文档保存分类失败后切换 B，B 不显示 A 的错误。
8. 删除前展示真实影响摘要；删除后其他文档、文件夹和标签不受影响。
9. 1080×720 下不截断核心操作，不出现横向页面滚动或移动卡片流。
10. 深浅主题均保持黑白主调、轻分隔和可辨识的真实状态色。
