# 移动端参考图风格重构设计规范

状态：已确认视觉方向，待进入实现计划
日期：2026-09-10
适用范围：`mobile/` 下的日程、求职目标、简历、我的四个主页面

## 1. 目标

将移动端从“白底列表 + 功能卡片”的现有视觉，收敛为用户提供的参考图风格：

- 浅色画布与白色工作区形成层次；
- 薄荷绿、粉色、淡黄、淡紫作为语义色，而不是装饰色；
- 大圆角、弱边框、低阴影、充足留白；
- 黑色主文字、灰色辅助信息、统一的小型动作箭头；
- 四个页面共享一套组件、字号、间距和交互状态。

本次只重构表现层与页面信息层级，不改变现有本地优先数据模型、路由和业务规则。

## 2. 参考图的移动端适配原则

参考图是宽屏工作区，移动端不直接照搬桌面左侧导航和双栏比例：

1. 保留当前底部四项导航（日程、目标、简历、我的），但改成轻量白色导航条与统一黑白图标；
2. 将参考图的“活动卡、统计卡、课程列表、日历”转成移动端纵向区块；
3. 只在足够宽的移动横屏或平板宽度启用双列目标卡，窄屏默认单列；
4. 参考图的背景装饰不作为业务图片复刻，避免小屏干扰内容和可读性；
5. 关键操作仍然可用：添加、编辑、删除、上传、切换主题、备份恢复和日历同步不因视觉改造而变成静态展示。

## 3. 全局视觉系统

### 3.1 画布与层级

- `--canvas`：非常浅的蓝灰/薄荷背景，作为页面外层；
- `--surface`：白色主工作区和主要卡片；
- `--surface-subtle`：白色工作区内的轻灰或极淡薄荷区域；
- 不使用厚重阴影、玻璃拟态或大面积渐变；
- 边框保持极轻，仅用于区分相邻内容，不用边框制造密集分块。

### 3.2 语义色

- 薄荷绿：已完成、当前进行、可继续的行动；
- 粉色：求职目标、面试活动或需要关注的记录；
- 淡黄色：下一步行动、待处理事项、学习进度；
- 淡紫色：统计、总结、成长趋势；
- 黑色：主标题、核心按钮、强操作；
- 灰色：辅助说明、时间、来源和不可用状态。

颜色只表达状态和优先级，不用于给每一块内容增加装饰噪音。

### 3.3 形状、字体与动作

- 统一使用 18–24px 圆角，按钮与卡片的圆角分级；
- 主标题为黑色中粗字，不使用参考图的英文大标题直接占满屏幕；
- 辅助信息统一使用灰色小字，时间和数量使用等宽数字特征；
- 卡片右上角动作统一为白色圆形小按钮或灰色箭头；
- 重要提交/创建按钮保留黑底白字，次要操作使用无填充按钮；
- 所有数据态必须有加载、空态、成功和失败反馈。

## 4. 页面设计

### 4.1 日程（第一优先级）

日程页必须最接近参考图，因为它是移动端的主展示页：

- 顶部只保留当前日期、时间和头像/快捷动作，不使用夸张页标题；
- “今天的活动”使用薄荷、粉、黄的小型活动卡，突出下一场面试；
- 月历作为右侧日历的移动端替代，保留月份切换、选中日期和事件圆点；
- 下方继续展示真实面试计划列表，使用公司图标、岗位/阶段、精确到分钟的时间；
- 添加日程、编辑、删除、提醒和手机日历分享保持真实可用；
- 没有安排时显示轻量空态，不虚构绑定岗位、公司或倒计时；
- 日程卡必须与数据中的 `jobProjectId`、事件类型和提醒状态一致。

页面权重：下一场行动 > 本月日历 > 面试计划列表。

### 4.2 求职目标

- 默认单列，保留用户可切换的两列布局；
- 每个目标使用一张彩色语义卡，展示公司、岗位、阶段管线、面试轮次和结果；
- 状态色只放在卡片背景或小型节点上，避免大面积高饱和色；
- 新建、阶段推进、面试轮次、结果标记、绑定简历和归档入口不改变；
- 空态和筛选状态要与参考图的卡片节奏一致。

### 4.3 简历

- 简历卡使用同系列身份图标和柔和色块，不使用 PDF/MD 作为主视觉；
- 上传、查看版本、追加版本、删除和目标绑定保持明确；
- 文件格式只在版本元信息中显示；
- 版本数量、更新时间和当前版本使用轻量文字层级；
- 列表卡不堆叠过多标签，主标题只承担“这份简历是什么”的识别任务。

### 4.4 我的

- 采用参考图的“个人头像 + 概览统计 + 设置入口”结构；
- 概览只展示真实本地数据：进行中的目标、日程数量、简历资产数量、下一场安排；
- 主题选择使用薄荷、浅色、深色等预览卡，而不是单一开关；
- 备份恢复、数据隐私和版本信息放在较低权重区域；
- 不引入假活动、假学习进度或虚构成长数据。

## 5. 响应式与交互规则

- 手机竖屏：所有主要内容单列，首屏优先展示今天的行动；
- 手机横屏/平板：目标卡和统计卡允许两列，但日程计划仍保持阅读顺序；
- 页面滚动容器只负责内容滚动，底部导航固定且不遮挡最后一项；
- 颜色、圆角、动效在浅色和薄荷主题中保持一致，深色主题只替换对比度 token；
- 交互状态必须可感知：选中、按下、加载、保存成功、删除确认、空态和失败重试。

## 6. 非目标

本阶段不新增：

- 云端同步或账号体系；
- 学习课程、社交和岗位爬虫；
- 额外的 AI 能力或新的数据对象；
- 为了复刻背景纹理而引入新的图片资源依赖；
- 只为视觉展示而添加的假数据。

## 7. 验收标准

1. 日程页在手机宽度下首屏可以理解“现在时间、下一场面试、本月安排和面试计划”；
2. 日程事件的公司图标、岗位、阶段、时间和提醒来自真实本地数据；
3. 目标、简历、我的页面都使用同一套颜色、圆角、字号和动作语言；
4. 所有核心入口仍可完成原有业务操作；
5. 空态、加载、删除确认和失败重试没有视觉或交互回退；
6. `npm test -- --run` 与 `npm run build` 通过；
7. 在手机竖屏与宽屏两种尺寸下截图复核，确认无横向溢出、底部导航遮挡或标题失衡。

## 8. 实施顺序

1. 更新移动端视觉 token、卡片、按钮、页头和 TabBar；
2. 优先重构日程页并完成一次视觉验收；
3. 将同一套组件迁移到目标、简历和我的；
4. 完成主题、空态、错误态和交互回归；
5. 更新版本号并提交移动端 UI 批次。
