# 求职项目最小模型

## 用户结果

用户可以为一个真实投递目标创建求职项目，给项目命名，关联一个本人保存的目标岗位和一个本人简历的具体版本，并在不再准备时归档或删除项目。

## 最小字段

- `id`：本地数据库标识；
- `user_id`：固定本地用户的数据边界；
- `name`：用户可修改的项目名称，1–120 个非空白字符；
- `status`：`active` 或 `archived`，由确定性接口改变；
- `job_description_id`：可空，只能引用当前本地用户的岗位；
- `resume_version_id`：可空，只能引用当前本地用户简历的版本；
- `archived_at`：归档时间，恢复时清空；
- `deleted_at`：软删除时间；
- `created_at`、`updated_at`：创建与修改时间。

求职项目不复制岗位或简历正文。第一版不增加优先级、录用概率、自动阶段判断、公共岗位和团队字段。

## 生命周期

```text
active ⇄ archived
   │         │
   └── soft deleted
```

- 创建时状态固定为 `active`；
- 归档和恢复使用显式接口，模型输出不能改变状态；
- 删除只软删除项目容器，不级联删除岗位、简历版本、证据或面试记录；
- 普通列表和详情永远排除软删除项目；
- 首版不提供恢复已删除项目的产品入口。

## 接口

- `GET /api/v1/projects`：列出当前用户全部未删除项目，进行中项目优先；
- `GET /api/v1/projects/{id}`：读取当前用户的一个未删除项目；
- `POST /api/v1/projects`：创建项目；
- `PATCH /api/v1/projects/{id}/name`：重命名；
- `PATCH /api/v1/projects/{id}/links`：修改或清空目标岗位、当前简历版本关联；
- `POST /api/v1/projects/{id}/archive`：归档；
- `POST /api/v1/projects/{id}/restore`：恢复；
- `DELETE /api/v1/projects/{id}`：软删除。

不存在或不属于当前用户的项目统一返回 404。字段校验失败或引用其他用户数据返回 400，响应不得暴露目标记录是否真实存在。

## 验收

- 可以创建、读取、重命名、归档、恢复和删除项目；
- 可以关联或清空本人目标岗位和本人简历版本；
- 跨用户的岗位、版本和项目均不可读取或绑定；
- 删除项目后默认查询不到，但被引用的岗位和简历版本仍存在；
- MySQL Flyway 迁移和 H2 测试结构均可重复验证。
