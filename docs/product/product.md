# ResumeGo 产品定义

## 定位

ResumeGo（职达）是一款本地优先、证据驱动的 AI 求职工作台。它帮助求职者围绕一个真实岗位，持续整理经历、修改简历、准备面试并积累反馈。

它不是一次性生成简历的聊天工具，也不是替企业筛选候选人的招聘系统。

## 核心用户

主要用户是拥有课程、项目、竞赛或初步实习经历，但不确定如何针对岗位表达能力的学生和初入职场者。

典型用户具备以下特征：

- 正在准备实习、校招或初级岗位；
- 已经有真实经历，但材料分散且表达不稳定；
- 会针对不同岗位调整简历；
- 希望使用 AI，但担心内容失真和隐私泄露；
- 需要把面试暴露的问题转化为下一步行动。

## 核心任务

用户打开 ResumeGo，不是为了浏览功能，而是为了完成：

> 我准备投递一个具体岗位，希望知道现有证据是否足够、简历应该怎样调整，以及面试前还缺什么。

## 核心对象

### 求职项目

一次真实求职目标的容器，关联公司、岗位描述、使用的简历版本、准备状态、面试记录和下一步行动。

### 能力证据

用户提供的事实材料，包括项目、实习、竞赛、课程、技能使用场景、个人职责和可证明结果。证据是 AI 建议和简历表达的事实来源。

### 简历版本

某一时点的不可变快照。每次用户确认修改后产生新版本，并保留原文、建议、依据和差异。

### 反馈事项

来自诊断、岗位差距或模拟面试的可执行问题。反馈可以转化为补充证据、修改简历或专项练习，不直接覆盖已有内容。

## 核心闭环

```text
创建求职项目
→ 填写或导入目标岗位
→ 选择简历版本与能力证据
→ 查看可解释的问题和差距
→ 审核有证据依据的 AI 建议
→ 确认后生成新简历版本
→ 完成绑定该版本的模拟面试
→ 将反馈转化为证据、修改或练习
→ 进入下一轮准备
```

## 产品原则

1. 任务先于功能：界面围绕一次求职准备组织，而不是展示模块清单。
2. 事实先于表达：没有证据时先提示补充，不用流畅文案掩盖事实缺口。
3. 建议而非代替：AI 输出是可审查草稿，用户拥有最终决定权。
4. 版本而非覆盖：重要修改可回看、可比较、可恢复。
5. 解释而非神秘分数：优先展示问题、依据和行动，不用总分制造确定性幻觉。
6. 本地优先：敏感数据默认留在用户设备，外发范围清晰可见。
7. 离线可用：模型不可用时，基础编辑、版本、导出和删除仍然工作。

## 非目标

当前不建设：

- 企业招聘、候选人筛选或 ATS；
- 招聘网站爬虫和自动投递；
- 依赖不明来源数据的公共岗位市场；
- 录用概率、薪资预测或绝对竞争力承诺；
- 在线课程、职业社交和复杂模板商城；
- 数字人、实时视频或语音面试；
- 强制注册、云端同步和团队协作后台。

## 替代方案与差异

用户不使用 ResumeGo 时，常见替代路径及其边界：

### 通用 AI 聊天（ChatGPT / DeepSeek / Claude）

- 能覆盖：单次简历润色、按岗位改写、生成面试问题——约占 v0.1 核心价值的七成；
- 缺失：经历与建议的证据绑定、版本追溯、面试反馈反哺下一版、数据本地保存、无编造约束。
- 结论：单次求助上通用 AI 更快，但「基于证据的持续准备」没有闭环。

### 模板站 / 简历工具（超级简历、Canva 等）

- 能覆盖：版式、导出、多版本管理；
- 缺失：岗位针对性判断、AI 建议的可追溯性、模拟面试与反馈闭环。

### 人工辅导（求职咨询、导师）

- 能覆盖：深度、个性化、真实反馈；
- 缺失：随时可用、成本、可持续的反馈记录。

### ResumeGo 的护城河

不是单点功能，而是**闭环**：

```text
能力证据 → 岗位针对性表达 → 版本可追溯修改 → 模拟面试 → 反馈转为下一步 → 证据与下一版
```

这条闭环要求「证据—建议—版本—面试—反馈」五者共享同一数据模型。通用 AI 与模板工具都只覆盖其中一个环节，无法形成闭环。**优先级排序必须以这条闭环为纲**：凡是让闭环更完整或更可信的事先做；与闭环无关的装饰性功能（视觉精修、日历等）后置。


## 产品成功标准

第一项核心指标是：新用户能否在没有开发者指导的情况下，围绕一个真实岗位完成一次有依据的简历迭代。

同时满足：

- AI 建议能够追溯到用户证据；
- 用户能理解每次修改发生了什么；
- 模型失败不会导致已有内容丢失；
- 用户能够导出、备份和彻底删除数据；
- 安装、启动和更新不要求用户配置开发环境。
