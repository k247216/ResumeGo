# 职达 Career OS V2 路线图

Status: Active
Updated: 2026-08-22

## 版本策略

- V1 是已发布维护线，由独立流程负责修复和 Release。
- V2 是当前产品开发线，只承接 Career OS 新能力。
- V2 早期与 V1 并行安装并使用独立数据目录。
- V2 必须显式、可验证地迁移 V1 数据，不能原地破坏 V1 工作区。
- `main` 是唯一长期分支；各阶段使用隔离 worktree 和短期分支。

## V2-F0｜产品与运行边界

目标：让 V2 成为可独立开发、安装和验证的产品线。

进度（2026-08-22）：Preview 应用身份和运行数据目录隔离已完成。应用 ID 为 `com.resumego.careeros.preview`，显示名为“职达 Career OS Preview”，数据目录名为 `ZhidaCareerOSPreview`；前端 149 项、后端 294 项测试和前端生产构建通过。V1 数据迁移预检与导入回执尚未实现，因此 F0 尚未完成。

交付：

- V2 产品与架构文档成为权威定义；
- Preview 应用标识、显示名和数据目录与 V1 隔离；
- V1 导入协议、预检结果和迁移回执；
- 空工作区与 V1 数据迁移测试。

退出条件：V1 和 V2 Preview 可以并行存在；V2 读取 V1 数据时不会修改来源。

## V2-F1｜Career Pipeline Foundation

目标：用稳定领域对象管理多个真实岗位机会。

进度（2026-08-22）：后端 Foundation、创建后阶段管理以及日程/模拟面试关联已完成。H2 schema 升至 V5、MySQL 增加 V25；`/api/v2/pipelines` 支持多 Pipeline 创建与查询、自定义初始阶段、阶段新增/重命名/完整排序、确定性阶段切换、追加式历史、归档与恢复，并可关联或重新绑定当前用户的现实日程与完整模拟面试计划。软删除的日程和面试计划不会继续出现在 Pipeline 响应中。后端 318 项测试通过。尚未完成 V1 数据迁移与 Pipeline UI，因此 F1 尚未退出。

交付：

- 多 Pipeline 创建、编辑、归档和恢复；
- 公司、岗位、JD 和生命周期状态；
- 可配置、有顺序的阶段实例；
- 追加式阶段历史；
- 简历版本、日程和面试的 Pipeline 关联；
- V1 `job_projects` 显式迁移。

退出条件：用户可以独立推进两条 Pipeline，自定义和切换阶段，重启后历史与关联不丢失。

## V2-F2｜Knowledge Base Reliable Library

目标：先成为可信、可管理、可检索的本地资料库。

交付：

- 本地文件导入和元数据；
- 可恢复的文本解析；
- 分类、标签、关键词搜索；
- 原文定位；
- 删除原文时清理全部派生内容；
- 文件解析与索引失败的重试机制。

退出条件：用户可以导入、检索、定位和彻底删除资料；失败不会损坏其他职业资产。

## V2-F3｜Knowledge Training Loop

目标：证明知识资产能够直接改善训练。

交付：

- 选择知识来源发起训练；
- 基础、深入和场景问题；
- 回答、追问和结构化反馈；
- 反馈引用来源片段或明确证据不足；
- 生成一个可接受、延后或忽略的下一步行动。

退出条件：一次知识训练能够从用户资料开始，以有引用的反馈和明确下一步结束。

## V2-F4｜Interview Engine 三模式

目标：在统一会话基础上提供来源契约清晰的三种面试。

交付：

- Role Based Interview；
- Knowledge Training Interview；
- Experience Simulation Interview；
- 会话开始上下文快照；
- 统一反馈事件；
- 中断恢复和历史回放。

退出条件：三种模式不会混淆知识来源，历史反馈能解释当时使用的 Pipeline、简历和资料版本。

## V2-F5｜Workspace Action

目标：让首页只回答“我现在最应该做什么”。

交付：

- 可解释的确定性行动排序；
- 一个主行动；
- 最近活动；
- 轻量成长反馈；
- 延后、忽略和完成动作；
- 无 AI 时的完整降级体验。

退出条件：首页所有展示都来自真实领域数据，不依赖写死示例或 AI 随机决策。

## V2-P1

- Resume Version 分支、对比与长期演进；
- Growth Feedback 趋势与薄弱点；
- 用户授权的 Calendar Sync；
- V2 正式原位升级评估。

## V2-P2

- Skill / MCP；
- Career Agent；
- External Action Layer 投递记录与辅助填写。

## 阶段守卫

每项工作进入开发前必须回答：

1. 它是否让职业资产在真实流程中被复用？
2. 数据来源、归属、删除和迁移是否明确？
3. AI 失败或未配置时，本地核心能力是否仍可使用？
4. 是否有不依赖真实个人数据和真实模型服务的验收方法？
5. 是否保持当前阶段可安装、可恢复、可继续升级？

不能回答其中任何一项的功能不进入当前阶段。
