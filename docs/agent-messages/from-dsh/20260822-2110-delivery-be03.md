## 状态机 / 端点

**Retry**：`POST /api/v2/knowledge/documents/{id}/retry`
- 仅当前用户 FILE + FAILED；COPY_FAILED（staging 副本仍存在，从记录相对路径安全移动）与 EXTRACTION_FAILED（source AVAILABLE，从受管 source 读取）可重试。
- INVALID_UTF8/校验失败/COMPLETED/RUNNING/缺失副本 → 409 + 稳定 code（NOT_RETRYABLE/STAGING_MISSING/SOURCE_UNAVAILABLE/ALREADY_RUNNING）。
- 条件更新 FAILED→RUNNING claim，并发第二次 409，不创建第二个 job；成功 upsert extracted content 并完成原 job，失败保持 FAILED（更新 errorCode）。
- 不接受上传字节或任意路径；不修改原始用户文件。

**删除**：
- `GET /api/v2/knowledge/documents/{id}/deletion-impact`：title、hasSource/hasContent/hasCategory/hasTags、一次性 confirmationToken（明文只返回一次，SHA-256 入库）、expiresAt（10 分钟）；不返回路径/hash/正文。
- `DELETE /api/v2/knowledge/documents/{id}` body `{confirmationToken}`：同一事务校验当前用户 + token 未失效未使用（常量时间比较）+ 创建 cleanup job（FILE 时）+ 删除 document（FK cascade 清 content/import job/category/tag relation/source metadata）。
- 受管副本在**事务提交后**（TransactionSynchronization afterCommit）删除；成功 job=COMPLETED，文件删除失败 job=FAILED（FILE_DELETE_FAILED）但文档保持已删除、搜索立即不可见。
- `POST /api/v2/knowledge/cleanup-jobs/{id}/retry`：仅 FAILED/PENDING；FAILED 先置回 PENDING 再执行一次；并发 409。
- 启动补偿 `KnowledgeCleanupStartupRunner`：只处理 PENDING（避免无限重试 FAILED），表缺失环境静默跳过。

**文件清理边界**：`KnowledgeFileStore.deleteManaged` 只接受 `knowledge/staging/{name}` 或 `knowledge/sources/{userId}/{name}`；normalize + prefix 越界校验 + 用户目录匹配，越界/他人目录直接拒绝。
