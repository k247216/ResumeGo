## 统一类型识别契约

新增 `KnowledgeFileTypes` 作为唯一类型判定入口，扩展名一律小写归一（去前导点）：

| 扩展名 | 判定 | 导入结果 | sourceExtension | mediaType（服务端判定，不信任客户端 MIME） |
| --- | --- | --- | --- | --- |
| md / txt | parseable | COMPLETED + 提取正文 | md / txt | text/markdown / text/plain |
| pdf / doc / docx | 仅元数据 | FAILED + `UNSUPPORTED_FORMAT` | pdf / doc / docx | application/pdf / application/msword / ...wordprocessingml.document |
| 其他 / 无扩展名 | unknown | FAILED + `UNSUPPORTED_FORMAT` | **unknown**（禁止伪装 NOTE） | application/octet-stream |

## 行为变化

- 旧逻辑：非 md/txt 一律抛 `UNSUPPORTED_TYPE` 拒绝且不留记录。新逻辑：任何合法文件名都可导入为 FILE 文档，安全副本落位（源 AVAILABLE）+ 元数据落库；不可解析类型不提取正文、job/文档 FAILED、稳定错误码 `UNSUPPORTED_FORMAT`（新增），**禁止假装可编辑**（编辑仍仅 md，TXT 只读，未知类型 NOT_EDITABLE）。
- `KnowledgeFileNames.parse` 不再对扩展名白名单；缺失/空扩展名 → `unknown`；路径字符/控制字符/超长文件名拒绝逻辑不变。
- `knowledge_source_files.mime_type` 由导入写入（原为 NULL 占位）；所有响应路径（import/list/detail/search/recovery）经同一 `normalizeExtension` 返回一致的 sourceFile/sourceExtension/availability。
- 重复内容、同名不同内容、跨用户隔离沿用 fingerprint + user_id 约束，行为不变；日志只输出错误码，不含正文/绝对路径/密钥。
