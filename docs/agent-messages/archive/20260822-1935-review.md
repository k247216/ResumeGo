# BE-01 审查退回：修复 MySQL 外键类型与生成键

审查结论：暂不集成 1babeab，只需修复两个真实 MySQL 阻断项，不扩大功能。

1. MySQL V26 外键类型不兼容：现有 users.id 是 BIGINT UNSIGNED，但 knowledge_documents.user_id / knowledge_source_files.user_id 以及相关主外键当前是 signed BIGINT。MySQL 会拒绝创建外键。V26 中所有 id、user_id、document_id 应与现有规范统一为 BIGINT UNSIGNED；表字符集/排序规则也沿用 utf8mb4_unicode_ci。
2. KnowledgeRepository 通过 key row 的固定列名 "ID" 取生成主键，只在当前 H2 表现下可靠；MySQL JDBC 通常不保证该键名。改用仓库现有模式 KeyHolder.getKey() 并做 null 检查，避免生产 MySQL 创建 NOTE 后无法取 id。

H2FileWorkspaceMigrationTest 的版本 5→6 属于迁移必需伴随修改，追认通过，不需要撤回。

只补最小针对性证据：静态断言 V26 FK 列为 UNSIGNED，以及 repository 使用可移植生成键；模块测试即可，不重复跑全量。回传一个修复 commit，随后立即集成并发 IO-01。
