## User result

桌面端用户可以从知识文档或搜索命中处打开、在文件管理器中定位当前文档的受管原文；renderer 永远不接收、不提交系统路径，浏览器开发模式不会伪装成功。

## Frozen capability contract

- Renderer 只向 preload 传正整数 `documentId` 和固定动作 `open | reveal`，不得传文件名、相对路径或绝对路径。
- Preload 暴露 `openKnowledgeSource(documentId)` 与 `revealKnowledgeSource(documentId)`。
- 两个方法只返回 `{ ok: true }` 或 `{ ok: false, code: string, message: string }`，不得包含本地路径、hash、正文或内部 token。
- Electron main 使用 workspace token 与仅 main 持有的 `X-ResumeGo-Internal` 调用内部端点；renderer 不能直接调用该端点。
- 内部端点为 `GET /api/v2/internal/knowledge/documents/{id}/managed-source`，只在 internal token 恒定时间校验通过后返回当前用户、`FILE + AVAILABLE` 文档的受管相对路径。
- 后端稳定失败：`SOURCE_NOT_FOUND`、`SOURCE_NOT_FILE`、`SOURCE_NOT_AVAILABLE`、`SOURCE_MISSING`；缺失或跨用户文档统一表现为 `SOURCE_NOT_FOUND`。
- Electron main 将相对路径解析到 V2 `dataDir/knowledge/sources/`，使用 `realpath` 再次确认真实文件仍在该目录内，并拒绝 traversal、目录、符号链接和越界真实路径。
- `open` 使用 Electron `shell.openPath`；`reveal` 使用 `shell.showItemInFolder`。返回 renderer 前把系统错误归一为稳定 code，不返回原始系统错误中的路径。
- 受管文件缺失时，后端把 source availability 更新为 `MISSING`；不删除文档或提取正文，用户仍可看到资料记录并在页面获知原文件缺失。

## Required functional scenarios

1. 当前用户 AVAILABLE FILE：open/reveal 成功，只返回 `{ ok: true }`。
2. NOTE、FAILED/STAGED/MISSING FILE：返回稳定失败，不调用 shell。
3. 外部 renderer、无 internal token、错误 token、跨用户 document：无法取得受管路径。
4. renderer 传 `0`、负数、小数、字符串或对象：IPC 在调用后端前拒绝。
5. `../`、绝对路径、sources 目录外路径、目录、符号链接及 symlink 逃逸：全部拒绝且不调用 shell。
6. 数据库标记 AVAILABLE 但文件不存在：返回 `SOURCE_MISSING`，source 变为 MISSING，文档与已提取内容保留。
7. `shell.openPath` 返回系统错误：renderer 只得到归一化消息，响应和普通日志均不包含本地路径。
8. 非 Electron 的浏览器开发模式：adapter 返回 `DESKTOP_REQUIRED`，不伪装已打开。

## Direct rejection

- renderer 接收或提交任意路径。
- 直接信任数据库相对路径而不做 realpath/regular-file 边界校验。
- 将 internal token 暴露到 preload、renderer、日志或响应。
- 用 `shell.openExternal` 打开文件，或允许 URL/网络路径。
- 文件缺失时删除文档、派生正文，或伪造打开成功。
- 顺带实现 Knowledge 页面、RAG、编辑器或文件夹监控。
