P0-1 浏览响应竞态：
knowledge store 的 load()/browseBy() 没有 request sequence。快速点击文件夹 A→B 时，较慢的 A 响应可能最后覆盖 B 列表，而 UI 仍显示 B。为 browse/list load 增加递增序列，只允许最新请求写 documents/error/loading；补一个乱序响应单测。

P0-2 保存结果必须诚实：
saveNoteContent 已完成 PUT 后，如果随后 getKnowledgeDocument 回读失败，目前进入 catch 并显示“保存笔记正文失败”，把已持久化成功误报为失败。拆开“保存正文”和“刷新元数据”：PUT 成功即更新正文缓存/返回成功；detail 回读失败只给局部“已保存，元数据刷新失败，可重试”提示，不能抛成保存失败。补对应单测。

P1 最小生命周期清理：
KnowledgeLibraryView 注册 window resize 但未在卸载时 removeEventListener。增加 onBeforeUnmount 清理，避免重复进入页面后监听器累积。顺手让收起导航/列表/检查器后把焦点移到对应恢复按钮（这是交付中声称的交互；若现有组件改动超过很小范围，可先只做监听清理并在报告中明确焦点项未完成）。
