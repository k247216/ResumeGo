阻断项：
1. 阶段推进当前不可用。PipelineView.handleTransition 先把 currentStageId 作为 target 调用 transitionStage，后端会拒绝“目标等于当前阶段”，因此真正的 PENDING 推进永远不会执行；并且 StageTrack 点击任意 PENDING 都未传递 stageId。修复为：点击 PENDING 时携带该 stage.id，确认框保存明确 targetStageId，确认后只调用一次 transitionStage。不要自动猜第一个 PENDING。
2. 失效关联无法看见或修复。契约要求缺失日程/面试对象显示“关联不可用”，但当前摘要只统计能解析的对象，管理框也只遍历现有对象，导致已绑定但加载不到的 ID 被隐藏且无法解除。摘要按 pipeline 的 ID 数量计数；管理框补出缺失 ID 行（如“关联不可用 #id”），并允许解除。
3. loadHistory 使用 void 调用但未消化 reject，接口失败会产生未处理 Promise。保留 store 的错误展示，同时 catch 掉调用层 reject。

验收只需补/改针对性测试证明：
- 点击指定 PENDING 只发一次且 targetStageId 正确；
- 缺失关联可见、可解除；
- 历史失败不产生未处理拒绝且错误可见。
