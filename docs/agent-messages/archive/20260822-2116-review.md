审查 2f52002：主要状态机可用，但暂不集成，请做一个最小修复提交。

阻断 1｜COPY_FAILED 文档删除会遗留 staging 文件
deleteDocument 只在 source availability=AVAILABLE 时记录 storedRelativePath；COPY_FAILED 是 STAGED + stagingRelativePath，当前会创建 relPath=null 的 COMPLETED job，实际 staging 副本永久遗留。
修复：删除 FILE 时为每个真实受管路径创建 cleanup job：AVAILABLE/stored path，以及非空 stagingRelativePath；两者同时存在则分别清理，不能用 null job 伪造完成。补 COPY_FAILED 删除后 staging 消失的集成测试。

阻断 2｜删除后仍长期保存文档标题与已完成路径
knowledge_cleanup_jobs.document_title 会在用户删除文档后继续保留个人文字，不是清理所必需；COMPLETED job 也继续保存 source path，与“彻底清理”冲突。
修复：V9/V29 尚未发布，直接移除 document_title 字段及 model/repository 参数。job COMPLETED 时清空 source_relative_path；FAILED/PENDING 保留路径用于恢复。测试断言完成后不保留标题/路径。

阻断 3｜重试进程崩溃后会永久卡 RUNNING
claimImportJobForRetry 把 job 置 RUNNING，但启动恢复只处理 cleanup jobs。若进程在移动/解析中退出，文档仍 FAILED、job 永久 RUNNING，后续永远 ALREADY_RUNNING。
修复：
- 启动恢复把“document仍 FAILED 的 RUNNING import job”重置为 FAILED，保留原 errorCode；
- COPY_FAILED 若 staging 已不存在但确定性的 stored target 已存在，按“文件已落位、数据库尚未完成”继续提取，解决移动后崩溃/事务失败窗口；
- 仍然不得接受任意路径。
补两项针对性测试即可，不扩大到 Electron 或新功能。
