结论：范围与主体设计正确，暂不集成；有两个真实功能问题需要最小修复。

1. [BE-02 阻断] 缺失 nullable 字段会被误当作解除关联
- UpdateCareerPipelineRequest 目前使用普通 Long record component。
- JSON 若遗漏 jobDescriptionId 或 resumeVersionId，Jackson 会得到 null，与显式 null 无法区分。
- 结果是客户端漏字段时静默清除已绑定 JD/简历，违反“五个字段都必须出现；显式 null 才解除”的冻结全量更新契约。
- 修复要求：让两个 nullable 字段在 JSON 中仍是 required；缺失返回 400，显式 null 正常解除。保持 Allowed files，不改公共异常体系。

2. [FE-02 阻断] mutation 成功后可能残留旧错误
- guardMutation 只在失败时写 errorMessage，成功时不清除。
- 用户第一次操作失败、第二次重试成功后，Pipeline 已更新但界面仍会暴露旧失败信息，状态与真实结果不一致。
- 修复要求：每次 mutation 开始或成功后清除旧 errorMessage；若本次失败仍写入当前错误并原样抛出。不要改变 pipelines/selection 的失败语义。

验证要求精简：
- BE 只补一个“遗漏 nullable 字段返回 400 且不调用 service”和一个“显式 null 仍可进入更新”的针对性验证。
- FE 只补一个“失败后再次成功会清除旧 errorMessage”的 store 场景。
- 本轮无需重复全量测试；完成最小修复并跑对应目标测试即可。最终集成后由 Core Controller 统一跑一次全量回归。
