# ResumeGo 架构说明

本文档区分“当前可运行架构”和“目标桌面架构”。目标架构描述迁移方向，不代表相关能力已经实现。

## 当前架构

```text
Vue Web Client
      |
   REST API
      |
Spring Boot 模块化单体
      |
    MySQL

Spring Boot → 外部模型 API
```

当前结构适合开发和验证业务，但要求用户准备浏览器、Java、Node.js 和数据库环境，不适合作为桌面产品直接发布。

## 目标桌面架构

```text
Electron 主进程
├── 窗口与应用生命周期
├── 文件导入导出
├── 安全存储
├── 更新与安装信息
├── Spring Boot 子进程管理
└── 受控 IPC
        |
Vue Renderer
        |
127.0.0.1 随机端口 + 单次会话凭证
        |
Spring Boot 模块化单体
├── resume
├── project
├── assessment
├── matching
├── optimization
├── interview
├── feedback
├── export
└── ai
        |
H2 文件数据库 / 外部模型 API
```

第一阶段选择 Electron，是为了最大限度复用现有 Vue 前端。Spring Boot 继续作为本地业务进程，随应用携带受控 Java 运行时；数据库从外部 MySQL 迁移到用户目录中的 H2 文件。

## 进程职责

### Electron 主进程

- 创建和管理应用窗口；
- 启动、健康检查和停止 Spring Boot 子进程；
- 选择用户数据目录和临时目录；
- 提供文件选择、导入、导出和备份能力；
- 通过系统安全能力保存模型密钥；
- 管理应用版本、更新状态和系统菜单。

主进程不实现简历评分、岗位匹配或面试业务规则。

### Vue 渲染进程

- 展示求职项目、简历、证据、岗位和面试流程；
- 保存可恢复的界面状态；
- 通过 HTTP 调用本地后端；
- 通过白名单 IPC 请求有限的系统能力。

渲染进程默认启用隔离，不直接获得任意 Node.js、文件系统或进程权限。

### Spring Boot 本地进程

- 承担业务用例、数据校验、事务和持久化；
- 隔离确定性规则与外部模型调用；
- 只监听本机回环地址；
- 使用启动时生成的随机端口和会话凭证；
- 接收退出信号并完成数据落盘。

### H2 文件数据库

- 每个操作系统用户拥有独立数据文件；
- 数据位置由 Electron 主进程确定并显式传递；
- Flyway 管理数据结构版本；
- 备份和恢复围绕数据库文件及附件目录进行；
- 从 MySQL 迁移前必须验证 SQL、字段类型和测试兼容性。

## 业务模块边界

- `project`：求职项目及其上下文关系；
- `resume`：简历、经历、能力证据和版本；
- `job`：用户保存的目标岗位，不承担公共岗位市场；
- `assessment`：确定性诊断维度、规则和解释；
- `matching`：必备项、加分项、未知项和确定性差距分析；
- `optimization`：AI 建议、依据、差异和采纳记录；
- `interview`：人工定义的面试流程和模型生成的内容；
- `feedback`：将面试问题转为证据、修改或练习事项；
- `export`：PDF 与数据导出；
- `ai`：模型适配、提示词版本、结构化校验和降级。

业务模块通过明确接口协作，不跨模块直接读写数据表。外部模型 SDK 只存在于 `ai` 模块。

## 关键数据流

```text
用户事实
→ 能力证据
→ 简历版本
→ 求职项目 + 目标岗位
→ 确定性问题与差距
→ 有证据依据的 AI 建议
→ 用户确认
→ 新简历版本
→ 绑定版本的模拟面试
→ 反馈事项
→ 下一轮证据与简历迭代
```

## 可信控制边界

- 模型可以抽取、归纳、改写、生成问题和提供解释性评价。
- 程序负责权限、最终分数、岗位排序、流程状态、数据校验和持久化。
- 模型输出必须经过版本化 Schema 和业务校验。
- 任何建议都不能直接覆盖简历或改变求职项目状态。
- 模型失败时返回可理解的降级结果，并保留用户已保存数据。

## 迁移顺序

1. 清理默认数据和 Web 产品入口，稳定核心对象。
2. 为现有核心流程补充前端测试和后端回归。
3. 验证 MySQL 到 H2 的迁移兼容性。
4. 增加 Electron 壳和 Spring Boot 生命周期管理。
5. 接入本地文件、备份、安全存储和安装包。
6. 完成升级迁移、签名和 GitHub Releases 发布链路。

在桌面壳稳定前，不同步重写前端框架或后端语言。
