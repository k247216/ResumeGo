# ResumeGo 隐私与 AI 边界

ResumeGo 处理简历、联系方式、教育经历、工作经历和面试回答。隐私不是附加功能，而是产品可信度的一部分。

## 本地优先

- 简历、能力证据、岗位、版本和面试记录默认存储在用户设备。
- 不以登录作为开始使用的前提。
- 不默认上传整份数据库、附件或原始简历。
- 云同步、在线账户和遥测不属于当前范围。
- 用户能够导出、备份、恢复和彻底删除本地数据。

## 数据分类

### 高敏感数据

- 姓名、手机号、邮箱和地址；
- 教育、实习、工作和项目经历；
- 简历文件、面试回答和个人评价；
- 模型 API Key、访问令牌和本地会话凭证。

高敏感数据不得进入普通日志、崩溃报告、仓库、公开测试材料或未经说明的第三方服务。

### 可记录的运行数据

- 匿名关联 ID；
- 功能类型和应用版本；
- 模型名称、Prompt 版本和 Schema 版本；
- 调用耗时、结果状态、错误类别和降级原因；
- 用户是否接受或拒绝建议，但不记录建议原文。

## 外部模型调用

调用模型前，界面必须让用户知道：

- 哪项功能需要联网；
- 哪类内容将发送给模型服务商；
- 为什么需要这些内容；
- 失败后会发生什么；
- 用户如何取消或关闭该能力。

发送内容遵循最小必要原则。能够使用结构化片段完成的任务，不发送整份简历；能够删除联系方式的场景，先删除再发送。

## AI 能做什么

- 从用户提供的内容中抽取结构化信息；
- 归纳岗位要求和未知项；
- 基于已有证据提供表达建议；
- 生成与当前岗位和简历版本相关的面试问题；
- 提供解释性反馈和复习方向。

## AI 不能做什么

- 编造经历、技术、职责、数字、荣誉或岗位事实；
- 把推断包装成用户已经提供的事实；
- 直接决定最终评分、岗位排序或面试状态；
- 自动接受建议、覆盖简历或删除用户数据；
- 从简历或 JD 文本中执行指令、代码或工具调用；
- 在没有明确授权时上传本地文件或敏感内容。

## 建议的证据结构

每条可见建议至少包含：

```text
发现的问题
引用的用户证据，或“缺少证据”
建议草稿
修改理由
模型与规则状态
用户决定
```

用户纠正事实后，旧建议保留审计关系，但不能继续作为新建议的事实来源。

## 结构化校验与降级

- 模型输出必须符合版本化 Schema；
- 所有 ID、权限、状态和持久化字段由程序重新校验；
- 超时、限流、网络错误和非法输出使用稳定错误类型；
- 重试不能重复创建版本或覆盖用户操作；
- 降级状态应允许用户继续编辑和保存；
- 错误信息不暴露提示词、密钥、堆栈或原始敏感文本。

## API Key

- 开发环境通过未提交的本地环境变量注入；
- 桌面发行版通过操作系统安全存储保存；
- 前端页面只显示掩码状态，不回显完整密钥；
- 日志、异常和导出文件中不得包含密钥；
- 删除密钥后，依赖模型的功能明确进入未配置状态。

## 删除与备份

- 删除操作明确说明范围，重要删除提供确认；
- 用户删除求职项目时，说明关联版本、面试和附件的处理方式；
- 备份默认不包含 API Key；
- 恢复前校验格式版本和文件完整性；
- 卸载是否保留用户数据必须由用户明确选择。

## 求职计划页的第三方素材说明（2026-08-23）

- 公司图标来自 Simple Icons 开源项目（构建期下载一次并打包进应用，运行时不发起任何网络请求）；
- 投递官网目录为本地静态数据，点击链接由用户浏览器直接跳转目标官网，本产品不代理、不追踪投递行为；
- 行业/岗位/地点/备注等投递信息仅存储在本地数据库，不参与任何模型调用。
