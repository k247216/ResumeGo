# AI 协作与日志政策

## 1. 三种协作模式

- 启发式：讨论需求、风险和替代方案，由人做决定。
- 精确式：对非禁飞区的明确任务生成或修改代码。
- 约束式：AI 在仓库规范、测试和文件范围限制内执行任务。

每次使用 AI 前必须明确任务、允许修改的范围和验收方式。

## 2. 禁止事项

- 使用 AI 生成三个禁飞区的实现。
- 将用户原始简历、联系方式、访问令牌或 API Key 发给开发 AI。
- 未审查、未测试就合并 AI 生成代码。
- 让 AI 自行扩展需求、添加依赖或改变架构。
- 用模型主观评分替代确定性业务算法。

日志保存到 `harness-docs/ai/ai-usage-log.md`，不得包含完整 Prompt 中的敏感数据。

## 4. 产品 AI 审计日志

产品运行日志至少保存：

- 请求关联 ID 和匿名用户 ID；
- 功能类型、模型、Prompt 版本；
- 调用耗时、成功状态和错误类别；
- JSON Schema 校验结果；
- 是否重试或降级；
- 用户是否采纳建议。

默认不保存原始简历、JD、面试回答和完整模型响应。

## 5. PR 审查

QA 需要确认：

- AI 生成部分已被作者理解；
- 新依赖和权限合理；
- 没有敏感信息；
- 测试覆盖验收标准；
- AI 日志完整；
- 未越过禁飞区。
