# 功能开发流程

## 1. Issue

PO 编写用户价值、范围、非目标和可验证的验收标准。复杂功能先更新架构或产品文档。

## 2. 人工设计

开发者确认数据流、API、失败路径和测试方案。涉及禁飞区时先提交人工设计与测试表，
再开始手写代码。

## 3. 实现

从 `dev` 创建功能分支，小步提交。AI 只能在 Issue 指定范围内参与，并同步记录 AI
使用日志。

## 4. 自检

提交 Merge Request 前执行：

```text
格式检查 → 静态检查 → 单元测试 → 集成测试 → 核心 Smoke Test
```

## 5. Review

至少一名非作者 Review。QA 检查验收标准、AI 日志、安全、测试和禁飞区合规性。

## 6. 验收与沉淀

PO 按验收标准操作，验收通过后合入 `dev`。架构选择进入 ADR，重复出现的问题转化为
自动检查或仓库规范。

## Bug 修复

```text
复现 → 增加失败测试 → 定位根因 → 最小修复 → 回归测试 → 记录根因
```

Bug 注入评测优先使用日志、测试和 Git diff 定位，不允许先进行无目的大范围改动。
