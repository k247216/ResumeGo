# Sprint 1｜最小基础逻辑闭环

## 1. Sprint 目标

用最少的页面和工程能力证明核心逻辑可运行：用户结构化录入一份有事实证据的简历，
粘贴一个目标岗位 JD，获得可解释的简历评分和岗位匹配结果，再由通义千问 Max 给出
一次有证据来源的修改建议；用户采纳建议后生成一个新的简历版本。

本 Sprint 以业务链路正确为第一目标，不进行产品化打磨。

Sprint 结束时必须完成以下现场演示：

```text
录入能力证据
→ 创建简历
→ 粘贴 JD
→ 解析岗位要求
→ 查看简历评分
→ 查看岗位匹配和缺口
→ 获取 AI 修改建议
→ 采纳一条建议
→ 生成并查看新简历版本
```

## 2. Sprint 范围

### 本 Sprint 必须完成

- 能力证据的录入与查询；
- 简历创建、查询和版本管理；
- JD 录入和结构化解析；
- 简历多维度评分及解释；
- 单个简历与单个 JD 的匹配及缺口说明；
- 千问 Max 生成结构化修改建议；
- 建议的采纳、拒绝与版本生成；
- AI 调用审计；
- 核心接口测试和一条 Smoke Test。

以上能力均只实现支撑演示闭环所需的最小形态，不扩展批量操作、高级筛选和复杂配置。

### 本 Sprint 明确不做

- 用户注册、短信、OAuth 等复杂认证；
- PDF/Word 简历导入；
- 招聘网站爬虫和自动投递；
- 多岗位推荐与排序列表；
- 模拟面试；
- PDF 导出和模板编辑器；
- Redis、消息队列、向量数据库和微服务；
- 语音、数字人及实时通信。

## 3. 用户故事与验收标准

### S1-01｜录入能力证据

- 主责：成员 1
- 优先级：P0

作为求职者，我希望记录项目、实习、竞赛和技能证据，以便后续简历内容都有事实来源。

验收标准：

- 可以创建、查看和修改证据；
- 使用结构化表单录入，不做文件解析；
- 证据至少包含类型、标题、情境、行动、结果和技能标签；
- 结果允许为空，但界面明确提示补充量化结果；
- 删除被简历引用的证据时必须提示影响，不能静默删除；
- 输入校验失败时返回明确错误，不保存半条数据。

### S1-02｜创建简历和版本

- 主责：成员 1
- 优先级：P0
- 依赖：S1-01

验收标准：

- 可以通过能力证据创建一份简历；
- 简历至少包含基本信息、教育、项目/实习和技能；
- 修改后生成新版本，旧版本保持不变；
- 可以查看两个版本的原文差异；
- 手机号和邮箱不出现在普通日志中。

### S1-03｜录入并解析 JD

- 主责：成员 2
- 优先级：P0

验收标准：

- 用户可以粘贴岗位名称、公司名称和 JD 正文；
- 千问 Max 输出必备技能、加分技能、工作职责、经验和学历要求；
- 模型输出必须通过 JSON Schema 校验；
- 模型超时或格式错误时允许重试，并返回可理解的失败信息；
- JD 中的指令性文本不得改变系统 Prompt 或调用工具。

### S1-04｜简历多维度评分

- 主责手写：成员 1
- 测试主责：成员 3
- Review：成员 2
- 优先级：P0
- 标记：AI 禁飞区
- 依赖：S1-02

验收标准：

- 输出总分、各维度分数、扣分原因和评分规则版本；
- 相同输入和规则版本必须得到相同结果；
- 总分边界为 0—100；
- 空简历、缺失模块、极端长度和权重异常都有测试；
- AI 不生成评分算法，不决定最终分数；
- 主责成员能够逐行讲解实现。

### S1-05｜岗位匹配与缺口

- 主责手写：成员 2
- 测试主责：成员 3
- Review：成员 1
- 优先级：P0
- 标记：AI 禁飞区
- 依赖：S1-02、S1-03

验收标准：

- 输出总匹配度、必备项覆盖、加分项覆盖、经验匹配和未知项；
- 必备条件缺失会按人工规则影响最终结果；
- 相同输入必须得到相同结果；
- 至少准备 5 组固定简历/JD 样例验证排序和边界；
- AI 可抽取候选标签，但不能生成最终匹配分或排序结果；
- 主责成员能够逐行讲解实现。

### S1-06｜生成定向修改建议

- 主责：成员 2
- Review：成员 3
- 优先级：P0
- 依赖：S1-01、S1-03、S1-04、S1-05

验收标准：

- 建议包含原文、建议文本、理由、目标 JD 要求和来源证据 ID；
- 没有证据支持时只能返回“需要补充证据”，不能编造经历或数字；
- 模型输出通过 JSON Schema 校验；
- 用户可以逐条采纳或拒绝；
- AI 调用失败不修改原简历；
- Prompt 和模型名称均有版本记录。

### S1-07｜采纳建议并生成新版本

- 主责：成员 1
- Review：成员 2
- 优先级：P0
- 依赖：S1-06

验收标准：

- 采纳建议后创建新版本，不覆盖旧版本；
- 新版本记录来源版本和被采纳的建议；
- 重复提交不会创建多个相同版本；
- 可以查看修改前后差异；
- 拒绝建议不会改变简历。

### S1-08｜AI 调用适配与审计

- 主责：成员 3
- Review：成员 2
- 优先级：P0

验收标准：

- 千问 Max 的 Endpoint、模型标识和密钥通过配置注入；
- 业务模块通过内部 AI 接口调用模型，不直接依赖供应商 SDK；
- 记录请求 ID、功能、模型、Prompt 版本、耗时、状态和 Schema 校验结果；
- 日志不记录手机号、邮箱、完整简历和 API Key；
- 单元测试使用固定响应，不消耗真实模型额度；
- 超时、限流、非法 JSON 和供应商错误都有明确分类。

### S1-09｜测试基线与核心 Smoke Test

- 主责：成员 3
- 协作：成员 1、成员 2
- 优先级：P0

验收标准：

- 前后端测试可以分别通过一条命令运行；
- MySQL 集成测试使用隔离测试库或 Testcontainers；
- Smoke Test 覆盖 Sprint 目标中的完整用户路径；
- 每个 Bug 修复先添加能够复现问题的测试；
- 测试失败会阻止合并；
- 三名成员都能运行并解释测试结果。

## 4. 建议任务顺序

```text
工程骨架
├── S1-08 AI适配基础
├── S1-09 测试基础
├── S1-01 能力证据
│   └── S1-02 简历与版本
│       └── S1-04 简历评分
└── S1-03 JD解析
    └── S1-05 岗位匹配
        └── S1-06 修改建议
            └── S1-07 生成新版本
```

S1-04 和 S1-05 可以并行，但在数据结构和接口契约确认后才能开始实现。

## 5. Sprint 过程检查点

### 检查点 A｜设计完成

- 核心流程和页面草图确认；
- 数据模型确认；
- API 契约确认；
- 评分与匹配算法测试表由人完成；
- 每个故事都有验收标准。

### 检查点 B｜主链路可运行

- 前后端和 MySQL 可启动；
- 能力证据、简历和 JD 可以保存；
- 评分与匹配接口返回确定性结果；
- 千问调用可以被 Mock。

### 检查点 C｜Sprint 验收

- 完整演示链路通过；
- 自动化测试通过；
- AI 使用日志完整；
- 禁飞区代码和证据完整；
- 没有 P0/P1 未关闭缺陷；
- 三人都能讲解自己的代码。

## 6. Definition of Done

一个故事只有在以下条件全部满足时才能标记完成：

- 验收标准通过；
- 代码已合入 `dev`；
- 自动化测试通过；
- 至少一名非作者完成 Review；
- API、数据结构变化已更新文档；
- AI 使用情况已经记录；
- 不含密钥和敏感日志；
- 禁飞区任务具备人工设计、测试和逐行讲解证据。

## 7. Sprint 成功与失败判定

成功不是“写了多少页面”，而是上述演示链路能够在全新环境中稳定运行。

出现以下任一情况，Sprint 视为未完成：

- 评分或匹配结果直接由模型主观给出；
- AI 建议编造用户未提供的经历或数字；
- 采纳建议覆盖原始简历；
- 模型不可用时核心数据损坏；
- 禁飞区代码无法由主责成员解释；
- 只能在某一名成员电脑上运行。
