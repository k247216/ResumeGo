# Sprint 3｜产品化闭环与验收稳定化

## 1. Sprint 目标

Sprint 3 的目标是在 S1 基础逻辑闭环和 S2 求职工作台基础上，把「职达」推进到可演示、可复盘、可验收的产品化版本。

核心链路从“能跑通”升级为：

```text
选择岗位
→ 编写 / 选择简历版本
→ 评分与岗位匹配
→ AI 能力教练给出薄弱点和训练计划
→ 多面试官模拟面试
→ 整次复盘
→ 成长趋势快照
→ 回到简历工作台继续迭代
```

本 Sprint 不追求扩张新平台能力，而是优先保证主流程稳定、体验一致、数据可追溯、禁飞区边界清晰。

## 2. Sprint 范围

### 本 Sprint 必须完成

- 面试大厅产品化：支持“一次面试包含多位面试官多轮流程”；
- 面试对话评分产品化：展示单题、单轮和整次多轮面试的表现；
- 整次多轮面试复盘：复盘属于某一次面试计划，而不是手动勾选多个历史记录；
- 成长趋势持久化：完成整次复盘后写入后端快照；
- AI 建议升级为能力教练：输出薄弱点、行动建议和训练计划；
- 公司偏好 Profile 预留并接入 AI 建议上下文；
- 公司图标稳定化：重点公司使用本地 curated 图标，其他公司使用品牌色头像兜底；
- PDF 导出和简历模板体验完善；
- S3 自动化验证、AI 使用日志和禁飞区边界记录。

### 本 Sprint 明确不做

- 企业端 ATS / 候选人筛选；
- 录用概率、薪资预测；
- 大规模爬虫和自动投递；
- 数字人、语音和视频面试；
- 复杂公司画像后台；
- 让 AI 生成评分权重、岗位排序或面试状态机实现。

## 3. 核心产品形态

### 3.1 工作台

工作台仍然是主入口，围绕“当前简历 + 当前岗位”展开。用户从首页进入某份简历后，进入类似编辑器的工作台：

- 左侧编辑简历模块；
- 中间预览简历；
- 右侧展示岗位、匹配、评分和 AI 能力教练；
- 悬浮排版助手负责措辞 / 排版提案，并通过 diff 让用户决定是否应用到草稿；
- 面试入口继承当前简历版本和岗位上下文。

### 3.2 AI 能力教练

AI 建议不再承担“自动采纳生成新版本”的系统级闭环，而是转为能力教练：

- 诊断项目技术表达薄弱点；
- 根据目标岗位指出缺失事实或表达短板；
- 给出行动建议和 3 天训练计划；
- 对缺少证据的地方提出追问；
- 用户根据建议人工修改简历。

### 3.3 多轮模拟面试

一次面试计划包含多个面试官轮次：

```text
InterviewPlan
├── Round 1 / InterviewSession：技术面
├── Round 2 / InterviewSession：项目深挖
└── Round 3 / InterviewSession：HR / 综合面
```

每个 session 仍由人工状态机推进。计划层只负责组织轮次、复盘和历史归档，不参与状态转换。

### 3.4 面试复盘与成长趋势

完成所有轮次后，系统生成整次多轮复盘，并将清晰度、相关性、深度、准确性和综合表现写入 `interview_growth_snapshots`。

成长趋势用于展示不同简历版本 / 同一岗位下的面试表现变化，不参与简历评分和岗位匹配排序。

## 4. 用户故事与验收标准

### S3-01｜面试大厅与多轮面试计划

- 主责：成员 1 / 成员 3
- 优先级：P0

验收标准：

- 可以创建一次面试计划；
- 一次计划可以选择多位面试官并形成多个轮次；
- 面试绑定某个简历版本和目标岗位；
- 面试过程中未完成所有轮次时不能直接回到工作台；
- 历史记录以“一次面试”为单位展示，而不是散落为多个 session。

### S3-02｜面试评分产品化

- 主责：成员 3
- 优先级：P0

验收标准：

- 每道题展示清晰度、相关性、深度、准确性；
- 每位面试官轮次展示平均表现和薄弱维度；
- 整次面试展示最高维度、最低维度和训练方向；
- Mock 和真实 Prompt 均避免固定分数锚定；
- AI 评价不控制状态机，也不进入简历评分禁飞区。

### S3-03｜整次多轮复盘持久化

- 主责：成员 1
- 优先级：P0

验收标准：

- 只有所有轮次均为 `COMPLETED` 时才能生成整次复盘；
- 整次复盘写入 `interview_plans.summary_json`；
- 历史再次查看优先读取已保存结果；
- 删除历史记录为软删除计划，不物理删除问答数据；
- 旧的手动勾选多轮综合复盘入口不再作为主流程入口。

### S3-04｜成长趋势后端快照

- 主责：成员 1
- 优先级：P0

验收标准：

- 新增 `interview_growth_snapshots`；
- 生成整次复盘后写入快照；
- 前端成长趋势读取后端 API；
- 旧的已保存复盘可在查询时 backfill 快照；
- 快照不参与评分、排序或录用概率判断。

### S3-05｜AI 能力教练

- 主责：成员 1
- 优先级：P0

验收标准：

- AI 建议以薄弱点、行动建议和训练计划呈现；
- 不自动修改简历、不自动创建新版本；
- 缺少事实证据时提出追问；
- 公司偏好 Profile 只作为表达风格参考；
- Prompt 和日志明确禁飞区边界。

### S3-06｜公司图标与岗位展示稳定化

- 主责：成员 1 / 成员 2
- 优先级：P1

验收标准：

- 重点公司优先使用本地 curated 图标；
- 未命中真实图标时使用品牌色头像兜底；
- 不依赖外部 favicon 实时抓取；
- 岗位卡片和工作台当前岗位展示风格一致。

### S3-07｜S3 验证、日志与上传材料

- 主责：成员 1 / QA
- 优先级：P0

验收标准：

- 后端 `mvn verify` 通过；
- 前端 `npm run build` 通过；
- JaCoCo 指令覆盖率满足 85%；
- AI 使用日志记录 S3 关键 AI 参与；
- S3 阶段总结可用于课程材料上传。

## 7. 禁飞区说明

Sprint 3 没有生成或修改以下禁飞区实现：

- 简历评分权重与总分合成；
- 岗位匹配排序算法；
- 面试状态集合、转换表、题号推进和结束条件。

本阶段新增的 AI 能力均位于建议、评价、复盘和表达辅助层。模型输出必须经过结构化校验，不能直接控制状态、分数、排序、权限或版本写入。

## 8. 后续建议

- 将 AI 能力教练的数据结构从旧 suggestion 字段升级为独立的 `weakPoint / actionPlan / trainingPlan`；
- 将公司偏好 Profile 接入真实资料来源或人工审核后台；
- 补充最终部署脚本、演示脚本和 Bug 注入处置记录；
- 对前端大包进行代码分割，降低构建警告。
