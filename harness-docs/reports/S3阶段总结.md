# S3 阶段总结

S3 阶段围绕「职达」从可运行原型到可演示产品闭环的升级展开。当前系统已经形成“选择岗位—编辑简历—评分匹配—AI 能力教练—多轮模拟面试—整次复盘—成长趋势—回到简历继续迭代”的主流程。与 S2 相比，本阶段的重点不再是增加零散功能，而是把简历工作台、AI 建议和模拟面试统一到一个求职成长闭环中。

在模拟面试方面，系统引入了 plan 级多轮面试概念，一次面试可以包含多位面试官，每位面试官对应一个独立轮次。计划层只负责组织轮次、历史归档和整次复盘，不参与面试状态机转换。所有轮次完成后，系统可以生成整次多轮复盘，并把复盘结果保存到 `interview_plans.summary_json`，历史记录再次查看时优先读取已保存结果。

在面试评价方面，单题回答已展示清晰度、相关性、深度和准确性四个维度，单轮面试展示平均表现和薄弱点，整次面试展示最高维度、最低维度和训练方向。此前评价分数容易固定在相近区间的问题也进行了处理：Mock 评价改为根据回答质量产生差异化分数，真实 Prompt 去除了固定数字示例，减少模型被样例分数锚定的风险。

在成长趋势方面，系统新增 `interview_growth_snapshots` 表，用于固化一次完整多轮面试后的能力表现快照。生成整次复盘后，后端会写入清晰度、相关性、深度、准确性和综合表现等数据；前端成长趋势不再依赖临时聚合，而是通过后端接口读取快照。对于旧的已保存复盘，如果尚未生成快照，查询时可以基于已有评价和总结进行 backfill，不需要重新调用 AI。

在 AI 建议方面，右侧建议面板从“采纳建议并自动生成新版本”调整为“AI 能力教练”。AI 不再直接修改简历，也不再负责创建新版本，而是输出薄弱点、行动建议和训练计划，引导用户自己回到对应模块修改。对于证据不足的内容，系统通过追问提示用户补充事实，避免 AI 编造经历。公司偏好 Profile 也已完成基础接入，当前仅作为表达风格参考，不能用于评分、排序、录用概率或事实断言。

在工程质量方面，S3 相关代码通过了后端全量验证、前端构建和覆盖率门禁。当前后端 `mvn verify` 通过，前端 `npm run build` 通过，JaCoCo 指令覆盖率为 85.19%，满足课程测试覆盖要求。AI 使用日志已经记录本阶段 AI 辅助内容，并明确说明未触碰简历评分、岗位匹配排序和面试状态机三个禁飞区。

本阶段仍保留的后续工作包括：将 AI 能力教练的数据结构进一步独立化，完善公司偏好 Profile 的真实资料来源，补充最终部署和演示脚本，继续优化前端包体积与构建警告。整体来看，S3 已经完成了核心产品闭环的稳定化和产品化，为最终演示和验收打下基础。
